# A2A Repair Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make A2A genuinely work end-to-end — `.withA2A()` currently binds no port, runs no agent, and the package's own client cannot talk to its own server. A2A is being **kept and repaired**, not deleted.

**Architecture:** Serving moves from an inert Layer to an explicit `await agent.serveA2A()` that returns a handle, because the agent does not exist at layer-construction time (that layer *is* part of the runtime that builds the agent). The package server becomes the single implementation: `rax serve`'s ~120-line hand-rolled duplicate is deleted and pointed at it, which is also what prevents the `EADDRINUSE` that repairing the bind would otherwise cause. The protocol contract is resolved **in favor of the A2A spec**, and the three in-repo clients are corrected to match.

**Tech Stack:** TypeScript (strict), Effect-TS, `bun:test`, `secureServe` from `@reactive-agents/runtime-shim`.

**Spec:** The A2A protocol itself, as already encoded in `packages/a2a/src/types.ts` (`A2ATaskSchema`, `SendMessageParamsSchema`, `JsonRpcResponseSchema`). That file is the binding authority for every shape decision in this plan.

## Design Note: the spec wins, not the hand-roll

Three in-repo clients expect `message/send` → `{ taskId }`:
`packages/a2a/src/client/a2a-client.ts:62`, `packages/runtime/src/builder/build-effect/remote-agent-tools.ts:104-106`, and the CLI's own server contract (`serve.ts:205`). The package server instead returns the full task (`http-server.ts:55`), whose id field is `id` (`types.ts:136`). So the package's client and the package's server genuinely cannot talk to each other.

The obvious fix — change the server to emit `{ taskId }` — is **wrong**, and this plan deliberately rejects it. The A2A spec's `message/send` returns a Task object; `A2ATaskSchema` already encodes that correctly with `id`, `status: { state, ... }`, and output in `artifacts[]`. The `{ taskId, status: string, result }` shape is a bespoke dialect invented by the CLI's hand-rolled server and copied by `remote-agent-tools`.

Making the server bug-compatible with our own hand-roll would permanently fork this implementation from the standard it exists to implement — an A2A server that no third-party A2A client can talk to is worth nothing. All three clients are in this repo and are ours to fix. **The server stays spec-shaped; the clients get corrected.**

## Global Constraints

- `packages/a2a/src/types.ts` is the authority for every wire shape. When this plan and that file disagree, the file wins — report the discrepancy rather than following the plan.
- Strict TypeScript. No `any`, no new `as unknown as` (repo gate ceiling 78, currently 79 — do not add). Task 4 *removes* several `any`s.
- `packages/a2a` must never depend on `@reactive-agents/runtime`. Its deps are `@reactive-agents/core` + `@reactive-agents/runtime-shim` only, and `flags.ts:14-15` documents this as deliberate. The agent arrives as an injected `TaskExecutor` closure.
- Library code must never call `process.exit`. `apps/cli` may.
- Network ingress goes through `secureServe` only — it is loopback-by-default and throws on a non-loopback bind without a token. Never call `Bun.serve` directly.
- Do not change `TaskExecutor`'s signature (`task-handler.ts:9`): `(input: string, taskId: string) => Effect.Effect<string, A2AError>`. It is already the right seam.

describe("A2A HTTP server, live on a real port", () => {

    const executor = (input: string) => {

      return Effect.succeed(`echo: ${input}`);

      configuration: { blocking: true },

    expect(res.id).toBe("req-42");
    await handle.stop();
  });

  it("cancels an in-flight task instead of reporting TASK_NOT_FOUND", async () => {
    // A never-settling executor keeps the task in `working` so cancel is legal.
    const handle = await startTestServer({
      port: 0,
      executor: () => Effect.never,
    });
    const send = await rpc(handle.port, "message/send", {
      message: { role: "user", parts: [{ kind: "text", text: "slow" }] },
    });
    const cancel = await rpc(handle.port, "tasks/cancel", { id: send.result.id });
    expect(cancel.error).toBeUndefined();
    expect(cancel.result.status.state).toBe("canceled");
    await handle.stop();
  });

  it("returns the task immediately in non-blocking mode", async () => {
    const handle = await startTestServer({
      port: 0,
      executor: () => Effect.never,
    });
    const send = await rpc(handle.port, "message/send", {
      message: { role: "user", parts: [{ kind: "text", text: "bg" }] },

- [ ] **Step 3: Collapse the two task stores**

`createA2AHttpServer` makes its own store (`http-server.ts:45`) and `createA2AServer` makes a second (`a2a-server.ts:28`). `handleMessageSend` writes the http store; `handleTasksCancel` reads only the A2AServer store via `server.cancelTask` (`http-server.ts:117`). Every cancel of a real task therefore returns TASK_NOT_FOUND. `handleTasksGet` accidentally hides the same split with a local-first fallback (`:101-106`).

Fix at the boundary: there must be **one** store. Preferred direction — have `createA2AHttpServer` use the `A2AServer` service's store rather than making its own, so `getTask`/`cancelTask` and `handleMessageSend` operate on the same map. If `A2AServer` does not expose a way to write a task, add one (and delete the now-unnecessary local-first fallback in `handleTasksGet`, which exists only to paper over this bug).

Verify no other reader depends on the split before changing it: `grep -rn "createA2AServer\|A2AServer" packages apps --include=*.ts | grep -v dist`.

- [ ] **Step 4: Echo the request id**

`http-server.ts` hardcodes `id: null` in every success response (`:55, :104, :107, :118, :140`) while the error path correctly echoes it (`:226`). JSON-RPC 2.0 requires the response id to equal the request id. Thread the incoming `id` through `routeRequest` into each handler and echo it.

- [ ] **Step 5: Honor `configuration.blocking`**

`SendMessageParamsSchema` declares `configuration.blocking` (`types.ts:303`) and nothing reads it. `handleMessageSend` (`task-handler.ts:47-85`) always awaits the executor inline, so every send blocks until the run completes.

Change `createTaskHandler`'s `handleMessageSend` to branch:
- `blocking: true` → current behavior (await the executor, return the completed task).
- otherwise (the spec default) → store the task as `working`, fork the executor so it updates the store on completion/failure, and return the `working` task immediately.

Use Effect's forking (`Effect.forkDaemon` or equivalent) rather than a floating promise, so the fiber is supervised. Confirm the surrounding code's convention before picking.

- [ ] **Step 3: Implement `serveA2A()`**

Add to `ReactiveAgent`, next to `run()`. It bridges `agent.run()` into the `TaskExecutor` seam and uses `generateAgentCard` (the canonical generator — never the inline card being deleted in Step 4):

```ts

     * Serve this agent over the A2A protocol. Returns once the port is bound.
     *
     * Other agents discover it at `/.well-known/agent.json` and invoke it with
     * JSON-RPC `message/send`.
     */
    async serveA2A(options?: {
        readonly port?: number
        readonly description?: string
        readonly hostname?: string
        readonly token?: string
    }): Promise<{ readonly port: number; stop(): Promise<void> }> {
        // Executor seam: (input, taskId) => Effect<string, A2AError>
        // taskId is A2A's id; map it onto the run so cancel() can reach the run.
        // ...construct the card with generateAgentCard({ name, description, url }),
        // build the server layer with createA2AHttpServer(port, executor),
        // call start(), and return { port, stop }.
    }
```

Two details the implementer must settle by reading the code, not guessing:
- **Cancel correlation.** `agent.cancel(taskId)` (`reactive-agent.ts:2527`) signals the ExecutionEngine for *its* task id. A2A mints its own `taskId` (`task-handler.ts:11`), so passing the A2A id to `cancel()` cancels nothing — this is the same latent bug the CLI has today (`serve.ts:242`). Either pass the A2A `taskId` into `run()` via its `options.taskId` (it accepts one — see the `run()` signature) so the ids are the same, or maintain an explicit map. Prefer the former; verify `run({taskId})` actually adopts the id before relying on it.
- **Where the agent's name comes from.** `ReactiveAgent` has no `name` field — the builder's `_name` survives only as a prefix inside `agentId` (`builder.ts:2581`, `${self._name}-${Date.now()}`), so deriving a card name from `agentId` would embed a timestamp. Thread the real name through, or take it from `serveA2A(options)`. Say which you chose in the task report.

**Files:**

- [ ] **Step 1: Stop advertising streaming that does not work**

`streaming.ts:19-37` builds a `ReadableStream` whose `start(controller)` defines a `send` closure and then discards it (`void send;` — nothing ever enqueues). `handleMessageStream` (`http-server.ts:205-215`) awaits full completion and joins all events into one body: batch wearing an SSE costume. Meanwhile `generateAgentCard` defaults `capabilities.streaming: true` (`agent-card.ts:29`).

Advertising a capability a client can rely on and we do not implement is the worst of the three options. Default it to `false` until streaming is real, and let a caller opt in explicitly if they have implemented it. Implementing real SSE streaming is a **separate follow-up**, not this task.

- [ ] **Step 2: Wire or remove `basePath`**

`A2AOptions.basePath` is plumbed from the wither through `runtime-construction.ts:473` into `runtime-types.ts:511` and then dropped — `A2aExtraLayer` never received it (and is deleted by Task 2), and the server hardcodes `/`, `/agent/card`, `/.well-known/agent.json`. `builder/types.ts:740` documents `.withA2A({ port: 8000, basePath: "/api/agents" })` as a working example.

Either honor it in the server's routing or remove it from the type and the doc example. Wiring it is a handful of lines in the route matcher and is the better outcome; if it is removed instead, the doc example must go with it.

- [ ] **Step 3: Fix or remove the `setMessageHandler` stub**

`a2a-server.ts:31`: `setMessageHandler: () => Effect.sync(() => {})` discards its argument while the `Context.Tag` interface advertises it as the way to supply a handler. With `serveA2A()` supplying a real executor, this is redundant — remove it from the interface, or implement it. A public method that silently does nothing is worse than either.

- [ ] **Step 4: Delete genuinely dead code, each after a sole-caller grep**

Confirm zero non-test callers for each before deleting, and report the grep result per item:
- `generateId` (`a2a-server.ts:21`) — unused.
- `JsonRpcMethod` (`http-server.ts:32-38`) — unused *and* drifted (declares `tasks/sendSubscribe` and `message/stream`; `routeRequest` has a case for neither).
